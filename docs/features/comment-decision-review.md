# Jev 评论决策审核

AI 设置中新建 TypeSafe / Jev 提供商，填写 API Key，默认端点为 `https://api.typesafe.ai/v1`，默认模型为 `jev-latest`。将其分配给独立的「决策模型」；文本模型继续用于不确定结果的后台复核。

评论设置中开启反垃圾、AI 审核和决策审核。默认同步超时 1000 ms、最低置信度 0.9，可按部署地区的实际延迟调整。评论和回复使用相同规则；保留已有的站主和已登录读者免审策略。

确定安全直接返回 `published`，确定违规返回 `rejected`，低置信度、超时或服务错误返回 `pending` 并交给后台文本模型。要求人工审核时，即使模型通过仍返回 `pending`，直到管理员批准。模型审核状态独立于已读/未读；打开待审评论不会自动批准。

后台任务从数据库恢复未完成审核，最多尝试三次，持续失败转人工审核。编辑、删除和人工操作发生后，旧模型结果不能覆盖新状态。客户端通过提交返回的私有 receipt 查询状态；receipt 哈希保存在数据库，有效期七天，查询不返回评论正文。Yohaku 会保存 receipt，刷新后可继续查询；自动轮询两分钟后提供手动刷新。

## 部署顺序

迁移 `0040_comment_moderation.sql` 只添加列，先按现有 release-phase 流程执行迁移。旧版本不理解新增审核状态，因此本次升级须暂停评论写入并排空旧实例，再让全部实例运行新版本后恢复评论写入；不能让新旧版本同时处理评论。回滚旧版本前，同样须暂停写入并处理所有 pending/manual 记录，避免旧读路径公开这些内容。

部署后在 AI 设置配置服务端凭据并测试连接，再启用决策审核。API Key 不随代码提交。未配置决策审核时仍使用后台 AI 审核，新待审评论保持不可公开，直到审核完成。

## 本次验证

六个合成样本通过真实 Jev API，延迟 343–939 ms，覆盖安全、垃圾和不确定评论；这是小样本结果，不代表生产 P95。真实 PostgreSQL 与 HTTP 验证覆盖隐藏待审评论及回复、私有回执、后台恢复、人工审核和并发覆盖保护。前端使用实际提交 hook 与状态组件连接本地 Nest/数据库验证，AI 设置使用实际设置组件验证。
